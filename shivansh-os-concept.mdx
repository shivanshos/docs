## Project ShivanshOS: Concept Document

**Project ShivanshOS** is a Personal Operating System framework designed to accelerate Research & Development activities in defense-related UAV (Unmanned Aerial Vehicles) and drone technologies through AI-agentic backed infrastructure.\[1\]\[2\][3]

## Executive Summary

ShivanshOS establishes a zero-trust, self-hosted ecosystem that integrates high-performance compute clusters, self-hosted LLM infrastructure, and multi-agent AI systems to support defense UAV R&D.  The framework leverages Cloudflare Zero Trust for secure access, GitHub Enterprise for code management, and Ubuntu 26.04 as the foundational OS layer.\[4\]\[5\]\[6\]\[7\]\[8\]\[9\][10]

## Core Architecture Pillars

### 1. Identity & Access Management

**Domain Structure:**

- Root domain: `shivanshsethi.in` (portfolio hosting untouched)
- Subdomains:
  - `os.shivanshsethi.in` - Main OS portal
  - `login.shivanshsethi.in` - Authentication gateway
  - `dev.shivanshsethi.in` - Development environment
  - `registry.shivanshsethi.in` - Container/model registry

**Zero Trust Configuration:**

- Team name: `shivanshos`
- Team domain: `shivanshos.cloudflareaccess.com`
- Identity providers: Okta + Auth0 (dual IdP setup)\[7\]\[8\]\[9\][11]
- Internal identity: `*@shivanshsethi.in` email accounts
- External identity: Outlook, Google, iCloud integration
- Cross-domain support: `aiotize`, `aio3.ai`

**SSO Configuration:**

- Okta SAML integration with Cloudflare One\[8\]\[11\][12]
- Auth0 OIDC integration for application-level SSO
- Risk score sharing between Cloudflare and Okta for adaptive access\[12\][13]

### 2. High-Performance Compute (HPC) Cluster

**Infrastructure Specifications:**

- OS: Ubuntu 26.04 Desktop with Landscape management\[3\]\[10\][14]
- SSO integration via Ubuntu Pro + Cloudflare Access
- GPU-accelerated workloads (NVIDIA CUDA/AMD ROCm)\[15\]\[16\][17]
- Container orchestration via Docker + Kubernetes-ready

**HPC Workstation Components:**

- Multi-GPU setup for LLM inference
- Fast NVMe storage for model caching
- Network isolation via Cloudflare Zero Trust tunnels
- iPhone access through Cloudflare One mobile client

### 3. Self-Hosted LLM Studio

**Inference Engines:**

- **Ollama**: Rapid prototyping, CPU/GPU hybrid workloads\[3\]\[14\]\[15\]\[16\]\[18\][19]
- **vLLM**: Production-grade throughput (9x performance gap on H100)\[1\]\[2\]\[16\]\[17\][20]
- **Open WebUI**: Chat interface for all models\[14\][21]

**Framework Stack:**

- LangChain for RAG pipelines
- CrewAI for multi-agent orchestration\[4\]\[5\][6]
- Custom agent frameworks (Hermes, etc.)

**Model Management:**

- Centralized model registry at `registry.shivanshsethi.in`
- Versioned model storage with Docker volumes
- Quantization strategies (AWQ, FP8) for hardware optimization\[15\]\[16\][20]

### 4. AI Agent Ecosystem

**Supported Agents:**

- Hermes Agent
- Kimi
- Gemini
- Claude Code
- GitHub Copilot
- Custom Web UI agents

**Agent Configuration:**

- Monorepo structure with `AGENTS.md` workspace map[22]
- Role-Goal-Backstory framework for CrewAI[6]
- Tool assignment and execution tuning (`max_iter`, `max_rpm`, `max_execution_time`)[6]

## Technical Implementation Details

### Ollama Installation (Ubuntu 26.04)\[3\]\[10\]\[14\][19]

```bash
# Install via shell script
curl -fsSL https://ollama.com/install.sh | sh

# Or via Docker
docker run -d --gpus=all \
  -v ollama:/root/.ollama \
  -p 127.0.0.1:11434:11434 \
  --name ollama \
  ollama/ollama

# Configure for remote access
sudo systemctl edit ollama
# [Service]
# Environment="OLLAMA_HOST=0.0.0.0:11434"
# Environment="OLLAMA_NUM_GPU=999"
sudo systemctl restart ollama
```

### vLLM Installation\[1\]\[16\]\[17\][20]

```bash
# Create virtual environment
python -m venv vllm-env
source vllm-env/bin/activate

# Install vLLM with CUDA support
pip install vllm

# Launch OpenAI-compatible server
python -m vllm.entrypoints.openai.api_server \
  --model meta-llama/Llama-3.1-8B-Instruct \
  --quantization awq \
  --max-model-len 8192 \
  --port 8000
```

### Cloudflare Zero Trust + Okta Integration\[7\]\[8\]\[9\]\[11\]\[12\][25]

1. **Okta Side:**
   - Create SAML 2.0 app integration
   - Configure SSO URL with Cloudflare Access endpoint
   - Set Name ID Format to `EmailAddress`
   - Export X.509 certificate
2. **Cloudflare Side:**
   - Navigate to Zero Trust > Integrations > Identity providers
   - Add SAML provider with Okta SSO URL and Issuer ID
   - Upload signing certificate
   - Enable risk score sharing to Okta\[12\][13]
3. **Access Application:**
   - Create self-hosted application for each subdomain
   - Define policies with group/email checks
   - Validate CF_Authorization JWT at origin
