## Overview

Here's a complete plan to fabricate the **ShivanshOS infrastructure** using **Cloudflare, GitHub, Ubuntu VPS (Hostinger), Ollama-powered AI agents, and Mintlify documentation**. This setup creates an agent-driven infrastructure deployment system where AI agents (powered by Ollama) generate context and execute deployment tasks across your stack.\[1\]\[2\][3]

---

## Architecture Components

| Component | Purpose | Technology |
| --- | --- | --- |
| **VPS Host** | Self-hosted AI agents, Ollama, Open WebUI | Hostinger KVM Ubuntu 24.04 |
| **DNS & Edge** | DNS management, Workers, Access SSO | Cloudflare |
| **Documentation** | Technical docs for agents & infrastructure | Mintlify (docs.shivanshsethi.in) |
| **Code Repository** | Infrastructure as code, agent context | GitHub (shivanshos) |

| **Identity** | SSO for all @shivanshsethi.in addresses | Cloudflare Access + OAuth |

## Phase 1: Pre-requisites & Foundation Setup

### 1.1 Domain & DNS Configuration

**Cloudflare DNS Setup for shivanshsethi.in:**

1. Add `shivanshsethi.in` to Cloudflare (if not already)
2. Configure these DNS records pointing to your Hostinger VPS IP:
   - `vps.shivanshsethi.in` → A record → VPS IP (Proxy: orange cloud)
   - `docs.shivanshsethi.in` → A record → VPS IP (Proxy: orange cloud)
   - `dash.shivanshsethi.in` → A record → VPS IP (Proxy: orange cloud)
   - `@` (root) → A record → VPS IP (optional, or keep on Hostinger)\[4\][5]

## Phase 2: VPS Setup (Hostinger KVM Ubuntu)

### 2.1 Initial Server Configuration

SSH into your VPS (`ssh root@vps.shivanshsethi.in` or IP):

```bash
# Update system
apt update && apt upgrade -y

# Create non-root user
adduser deploy
usermod -aG sudo deploy

# Install essential tools
apt install -y curl git ufw docker.io docker-compose-plugin nginx certbot python3-pip
```

### 2.2 Ollama Installation (AI Agent Runtime)

Install Ollama for self-hosted LLM inference:\[3\]\[6\][7]

```bash
# Install Ollama
curl -fsSL https://ollama.com/install.sh | sh

# Start and enable service
systemctl start ollama
systemctl enable ollama

# Configure Ollama to listen on all interfaces
systemctl edit ollama
```

Add to the `[Service]` section:

```ini
Environment="OLLAMA_HOST=0.0.0.0:11434"
```

Then reload:

```bash
systemctl daemon-reload
systemctl restart ollama
```

### 2.3 Pull AI Models for Agents

```bash
# Infrastructure planning agent
ollama pull llama3.2:3b

# Code generation agent
ollama pull codestral:7b

# Documentation agent
ollama pull qwen2.5:3b

# General assistant
ollama pull mistral:7b
```

### 2.4 Open WebUI (Agent Dashboard Interface)

Deploy Open WebUI as the agent interaction layer:\[8\][9]

```bash
docker run -d \
  --name open-webui \
  -p 3000:8080 \
  -v open-webui:/app/backend/data \
  -e OLLAMA_BASE_URL=http://localhost:11434 \
  --restart always \
  ghcr.io/open-webui/open-webui:main
```

Access at `http://vps.shivanshsethi.in:3000`

### 2.5 Nginx Reverse Proxy with HTTPS

Configure Nginx for `vps.shivanshsethi.in`:

```nginx
# /etc/nginx/sites-available/vps.shivanshsethi.in
server {
    listen 80;
    server_name vps.shivanshsethi.in;
    
    location / {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Enable SSL with Let's Encrypt:

```bash
ln -s /etc/nginx/sites-available/vps.shivanshsethi.in /etc/nginx/sites-enabled/
nginx -t
systemctl reload nginx
certbot --nginx -d vps.shivanshsethi.in
```

## Phase 3: Cloudflare Access & OAuth SSO Setup

### 3.1 Cloudflare Zero Trust Configuration

1. Go to **Cloudflare Dashboard** → **Zero Trust**
2. Navigate to **Access controls** → **Applications**
3. Add self-hosted application for `dash.shivanshsethi.in`

### 3.2 Enable Managed OAuth

For SSO across all `@shivanshsethi.in` addresses:[10]

1. In the application's **Advanced settings** tab:
   - Enable **Managed OAuth**
   - Set **Allowed redirect URIs**: `https://dash.shivanshsethi.in/*`
   - Configure **Grant session duration**: 24 hours
   - Set **Access token lifetime**: 15 minutes
2. Create OAuth client credentials:
   - Note **Client ID** and **Client Secret**
   - Store as Cloudflare Worker secrets

### 3.3 Access Policies

Create policy to allow only `@shivanshsethi.in` emails:

- **Policy name**: ShivanshOS Team Access
- **Rule**: `Email Ends With` → `@shivanshsethi.in`
- **Action**: Allow

## Phase 5: Cloudflare Workers AI Agent Dashboard

### 5.1 Create Agent Dashboard Worker

Initialize Cloudflare Workers project:\[2\]\[16\][17]

```bash
npm create cloudflare@latest -- agent-dashboard
cd agent-dashboard
npm install agents @cloudflare/ai-chat ai workers-ai-provider zod
```

### 5.2 Worker Configuration (wrangler.toml)

```toml
name = "agent-dashboard"
main = "src/index.ts"
compatibility_date = "2025-09-01"

[ai]
binding = "AI"

[vars]
OLLAMA_BASE_URL = "https://vps.shivanshsethi.in"
DOCS_URL = "https://docs.shivanshsethi.in"

[[d1_databases]]
binding = "DB"
database_name = "agent-dashboard-db"

[site]
bucket = "./public"
```

### 5.3 Agent Dashboard Code Structure

Create input forms for:

- Cloudflare API token
- Hostinger VPS credentials
- Domain names
- OAuth client secrets
- Agent model selection

The dashboard collects these inputs and stores them securely in Cloudflare Secrets/KV, then triggers deployment agents.

### 5.4 Deploy Worker

```bash
wrangler login
wrangler deploy
```

## Phase 6: AI Agents for Infrastructure Fabrication

### 6.1 Agent Context Generation

Each agent receives context from chat conversations to execute specific tasks:

**Cloudflare Agent Context:**

- DNS record creation
- Workers deployment
- Access policy configuration
- OAuth client setup

**Hostinger Agent Context:**

- VPS provisioning verification
- SSH key management
- Firewall rules
- Resource monitoring

**Ollama Agent Context:**

- Model pulling
- API endpoint configuration
- Performance tuning
- Container orchestration

### 6.2 Agent Execution Flow

1. User inputs configuration via Agent Dashboard
2. Dashboard stores inputs in Cloudflare KV/Secrets
3. Trigger Cloudflare Worker to call Ollama API on VPS
4. Ollama generates infrastructure code (Terraform, bash, etc.)
5. Agents execute via Workers + VPS SSH/API calls
6. Progress logged to Mintlify docs automatically

## Phase 7: Complete Setup Instructions

### Quick Start Checklist

1. **DNS**: Point subdomains to VPS IP in Cloudflare[4]
2. **VPS**: Install Ollama, Docker, Nginx on Ubuntu\[3\][7]
3. **Models**: Pull required LLMs via `ollama pull`[6]
4. **Open WebUI**: Deploy container for agent interface[9]
5. **Cloudflare Access**: Configure SSO for @shivanshsethi.in[10]
6. **OAuth**: Enable Managed OAuth on dash.shivanshsethi.in application
7. **Mintlify**: Connect GitHub repo, deploy docs to docs.shivanshsethi.in\[12\][15]
8. **Workers**: Deploy agent-dashboard Worker with AI bindings\[16\][17]
9. **Agents**: Configure context in `/agents/context/` directory
10. **Test**: Access dash.shivanshsethi.in → input config → trigger deployment

### Security Hardening

- Enable UFW firewall on VPS: `ufw allow 22,80,443,11434`
- Use Cloudflare Access for all admin interfaces
- Store secrets in Cloudflare Secrets Manager
- Enable 2FA on GitHub, Cloudflare, Hostinger accounts
- Regular Ollama model updates: `ollama pull --force <model>`
